HTML y CSS: dos idiomas que aprendí a hablar al mismo tiempo

28 de abril, 2026 · 4 min de lectura

Hay una confusión muy común cuando uno empieza: creer que HTML y CSS son lo mismo porque siempre aparecen juntos. Yo la tuve. Durante semanas mezclé etiquetas con estilos en el mismo archivo, puse negritas con la etiqueta <b> donde debía ir un encabezado, y me frustré cuando algo se veía distinto en mi computador y en el de un amigo. El problema no era el código: era que no había entendido que estaba hablando dos idiomas a la vez.

El HTML responde a la pregunta ¿qué es esto?. El CSS responde a ¿cómo se ve?. Cuando separas las dos preguntas, todo se vuelve más claro. En este blog, el HTML de cada entrada es casi idéntico: un título, una fecha, una imagen, unos párrafos. Lo que cambia entre una entrada y otra es mínima. El CSS, en cambio, es el que decide que el título sea grande, que la imagen ocupe todo el ancho, que el texto tenga aire. Si mañana quiero cambiar el color de los enlaces, toco un solo archivo y se actualiza en todas las páginas. Esa es la verdadera ventaja de separar la estructura del estilo.

También aprendí que el CSS no perdona tanto como el HTML. Un punto y coma olvidado puede tumbar un bloque entero de estilos, y el navegador no siempre te dice dónde está el error. Toqué fondo una noche intentando que una imagen se centrara: había escrito margin: 0 auto en una etiqueta que no tenía ancho definido, así que no funcionaba. Cuando lo entendí, me sentí un poco tonto y un poco genio al mismo tiempo. Supongo que así es esto.
